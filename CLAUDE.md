# Explorer: notes for Claude Code

Flutter app "Explorer" (`com.synqixlabs.explory`), a universal file manager with
built-in viewers and tools, for **Android, Windows and Linux** (macOS builds too; see below). Repo:
`MSatyam-Mishra/explorer` (public). Owner: Satyam (MSatyam-Mishra).

## Toolchain and commands

- Flutter 3.44.1 stable, Dart 3.12. Android SDK (AVD `explorer_test`, Play Store image, android-37.1 16 KB pages, x86_64: start it with `-no-window -gpu host`, detached from the shell, as `swiftshader_indirect` crashes on the app's blur, and a background job's time limit kills it; drive it with `adb shell input`, `uiautomator dump` and `screencap`, and `-s emulator-5554`, as a real phone is sometimes connected over Wi-Fi and `adb -e` then refuses or hits the wrong one. Copies of several GB make its low-memory killer kill everything, the launcher too: that's the emulator, not the app, so test with under 1 GB). Rust is installed on the main PC; `super_drag_and_drop` (cargokit) uses precompiled binaries.
- Android builds download libmpv's jars from GitHub in Gradle: on this PC Java's IPv6 route times out, hence `-Djava.net.preferIPv4Stack=true` in `android/gradle.properties`. They land in `build/media_kit_libs_android_video/`, so `flutter clean` fetches them again.
- If an Android build fails with `package dev.flutter.plugins.integration_test does not exist`, delete `android/app/src/main/java/io/flutter/plugins/GeneratedPluginRegistrant.java` (not tracked) and run `flutter pub get`. It came up after running tests just before building. Check `flutter build`'s exit code, as piping it through grep hides a failure and leaves the old APK there to install.
- Windows builds need `nuget` on the PATH (flutter_inappwebview, local_auth). On the main PC it comes from `winget install Microsoft.NuGet` (user scope). If a build says "Failed to install nuget package", check the `NUGET` line in `build/windows/x64/CMakeCache.txt` points at a nuget.exe that exists. Inno Setup 6 is installed for the user too (`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`) to build `packaging/windows/explorer.iss` locally.
- Processes started from Claude Code can't open the Windows clipboard, and while the screen is locked nothing can (and Flutter draws no frames, so window captures come out blank). Clipboard and drag tests need an unlocked desktop.
- macOS (a MacBook, Xcode 26, CocoaPods, rustup): `flutter build macos --release` gives `build/macos/Build/Products/Release/Explorer.app` (universal, macOS 12+, sandbox off). `super_native_extensions` compiles Rust through a native-assets hook (toolchain 1.97.1), so rustup must be installed. The app is ad-hoc signed (no Developer ID), so other Macs show a Gatekeeper warning; a DMG is made with `hdiutil create -srcfolder`.
- `flutter analyze lib test`: the only known findings are old ones in `lib/core/services/driver/mass_storage_driver.dart`, `lib/core/services/usb_host_service.dart` and `plugins/vocsy_epub_viewer-main`.
- `flutter test`: about 370 tests, a little over a minute. Screenshots: `SCREENSHOTS=1 flutter test test/screenshots` writes `build/screenshots/*.png` (`styles_screens_test.dart` shows every style, `tabs_screens_test.dart` the Windows title bar). On a device: `flutter test integration_test/image_text_test.dart -d <device>`; `integration_test/icon_strokes_test.dart` checks the lighter icon font, `thumbnails_test.dart` each kind of thumbnail, `system_icons_test.dart` Windows' icons and `glass_test.dart` the blurred menus and sheets; the last two also write `build/screenshots/*.png` from the real engine (system icons, This PC and the blur don't show in plain widget tests).
- Widget tests run on a fake clock, so real file I/O must go inside `tester.runAsync` (the `settle()` helpers alternate `runAsync` and `pump`). Under `FLUTTER_TEST` the app uses an in-memory clipboard, no folder watching, no native drag and drop and no OCR in the viewer. Opt-in: `EXPLORER_REAL_CLIPBOARD=1` (real Windows clipboard test), `EXPLORER_FFMPEG=path` (converter tests).
- Long Python edit scripts: write them to a file and run with `python -I -X utf8 script.py` (bash heredocs with quotes break). Don't run `dart format` on whole files that aren't already formatted.

## Map

- `lib/main.dart`: startup. A file sent from another app is the first screen (closing it returns to that app); a shared link, a notification or a shortcut opens over the explorer, pushed in the second frame, and `onNavigationNotification` tells Android who handles Back (WidgetsApp's own handler ignores it when the app was already resumed at the start, so Back would leave the app). `BackgroundMode.instance.init()` runs on desktop; `MaterialApp.builder` shows only `TasksView` while in tasks mode, with the app kept alive behind it. On desktop the home is `TabbedExplorer`.
- `lib/features/explorer_tabs/`: tabs (desktop). `ExplorerTabs.instance` holds the window's tabs; `TabbedExplorer` shows the tab bar and one nested `Navigator` per tab (viewers open inside the tab). On Windows `TabbedExplorer.prepareWindow()` hides the system title bar (window_manager `TitleBarStyle.hidden`) and the bar draws the caption buttons, a drag area and a top resize edge (no Windows 11 snap-layout flyout on the maximize button). macOS and Linux keep their title bar, with the tab bar under it. Keys: Ctrl+T/W/Tab/1-9; middle-click on a folder opens it in a background tab.
- `lib/core/theme/`: `app_style.dart` (Options > Style: `AppStyle` standard/macos/windows/sweet/dracula, their colour schemes, and `AppLook`, a ThemeExtension read with `context.look`: folder colours, `iconColor`/`tint` for colourful icons, Finder's sidebar tint, `iconPack` (assets/icon_themes: Sweet folders and Dracula Icons, both GPL-3.0, credited in `app_licenses.dart`), `systemIcons`), `icon_strokes.dart` (loads `assets/fonts/app_icons.ttf` under the default Lucide family, so every `LucideIcons.x` in the app changes without touching it: `tool/icons/build_icon_font.py` builds it from Lucide's 1.55 px weight with the icons in its `HI_ICONS` redrawn from `assets/Hi-icons`; folder and file icons stay Lucide on purpose, and so does what the pack lacks, such as arrows, chevrons, copy, cut, paste, share and save. Use `LucideIcons`, not Material's `Icons`, and add new ones to `HI_ICONS` if the pack fits), `app_theme.dart`, `theme_preferences.dart` (`app_style` key).
- `lib/features/file_explorere/` (the folder name's typo is real; keep it):
  - `screens/file_explorer_screen.dart`: the browser. It handles clicks, keys (Ctrl+C/X/V/A/N/F, F2, F5, Del, Esc), right-click menus, drag and drop, and group headings.
  - Virtual folders (`ExplorerPaths.isVirtual`): This PC, on computers categories (`explorer://category/Video`; `LocalFileRepository.categoryFiles` lists them), and what apps have saved (`explorer://social/whatsapp[/Tab]`; `core/services/social_files.dart` knows each app's folders, `widgets/social_tabs.dart` shows All files and a tab per folder). Anything that writes into "the current folder" must check `isVirtual`. macOS Photos and Video and all phone categories keep their own screens (`CategoryViewerScreen`, `FileCategoryScreen`). This PC has its own tiles (`widgets/this_pc_view.dart`) and no Cut, Rename or Delete.
  - Selection on computers: a click selects, Ctrl adds, Shift stretches; while the checkboxes show (`isSelectionMode`) a click ticks or unticks. The arrow keys, Home, End and Page keys move through `displayEntities`, Shift stretching from `_clicks.anchorPath`. `widgets/selection_band.dart`: dragging from anything that doesn't grab an item draws a band (`SelectionBand`); `itemDragPart` (a `MetaData`) marks what grabs an item: a row's icon and name, a whole tile, or a whole row once selected. `ShownItems` (one per bloc) knows the built items, for the band and for scrolling to the arrow keys' target. `_BrowserKeys` holds the keyboard: a text field that lets go of it leaves it on the page's focus scope, above the shortcuts, so it takes it back from there.
  - New folder makes the folder at once and renames it where it's shown (`createFolder`, `LoadDirectory(rename:)`, `renamingPath`, `widgets/inline_rename.dart`). F2 still opens a dialog.
  - `widgets/new_file_button.dart` (the + next to New folder) and `core/services/new_files.dart` (`NewFiles.kinds` and their blank contents; the menu's first row picks which show, saved as `new_file_kinds`, Text and Word at first). A new file opens in its editor from a blank in a temporary folder and only gets its name, and its place in the folder, at its first save: every editor's save asks `UntitledFiles.saveTarget` first, so a new editor must too. Kinds with nothing to type in (`NewFileEditor.none`: PDF, pictures, archives, .odp) ask for a name first. Office and OpenDocument files are built in code, except `assets/new_files/blank.xls` (made with xlwt) and `blank.pptx` (python-pptx's template, MIT, with one title slide: the viewer refuses a deck without slides). `.doc` is rich text under that name, which Word opens; there's no `.ppt`, as nothing here can write one. Checked with python-docx, openpyxl, xlrd, python-pptx, odfpy and pypdf, not yet in Office itself. Phones have no room for it in the header: their round + button and the empty folder's New file open `showNewItemSheet`.
  - `explorer_zoom.dart`: icon size (`ExplorerZoom`, Ctrl+wheel, pinch, Ctrl+plus/minus, Options) and `ZoomedGridDelegate`.
  - `bloc/`: the folder bloc (loading, sort, `GroupBy` groups, search, folder watching), `grouping.dart`, `folder_search.dart` (isolate search).
  - `widgets/`: `explorer_header.dart` (search box, sort/group menu, new window), `explorer_menu.dart` (popup menus with `submenu`), `file_drag_drop.dart`, `image_actions.dart` (Convert to ▸, Resize dialog).
- `lib/features/toolbox/` (sidebar, Tools): `toolbox_menu.dart` is a grid menu over the page, not a screen (closed by a tap outside or Esc; the owner asked for that), and `Tool` lists the tools. The pin, a right-click or a long press on a tool adds a shortcut through `core/services/app_shortcuts.dart`, with an icon drawn from the tool's and a route (`tool/ram_cleaner`) that `_screenFor` in `main.dart` opens: Android pins it to the home screen or fills the app icon's menu (`addShortcut` in `DeviceNative.kt`, the extra `explorer.route`), Windows writes a `.lnk` to the Desktop or Start menu through WScript.Shell (only the Desktop from an MSIX, through the `explory.exe` alias in its manifest), Linux a `.desktop` file (Desktop or `~/.local/share/applications`; AppImage, Flatpak and snap start through their own launcher), a Mac a small app bundle that runs `open -n` (Desktop or `~/Applications`). Computers pass `--route=`. Checked: Android on the emulator, the Windows `.lnk` in a test. Linux and Mac are only checked as text, never run. Each tool works in its system's own way. RAM cleaner (`core/services/toolbox/ram_cleaner.dart`: Windows `EmptyWorkingSet`; Linux drops the file cache through pkexec and macOS runs `purge`, both asking for the password and neither tried on those systems yet; Android before 14 closes background apps, and since Android 14 no app may, so it says so; it reports only what it measures), Memory cleaner (`junk_scanner.dart`: across shared storage on phones; on computers only folders meant for it, per system; only what's certainly safe is ticked at first), Duplicate finder (`duplicate_finder.dart`: size, then a hash of the start, then of everything), Video player (below) and Music player (a queue of all the audio).
- `lib/features/video_player/`: the one video player, for the Toolbox and any video opened in the app, on every system: libmpv through media_kit, Android too (`media_kit_libs_android_video` adds about 17 MB per ABI; `video_player` and `chewie` are gone). `video_library_screen.dart` is laid out after MX Player, as the owner asked: folders with a red count of what's new, the last played in the theme's colour, chips, a round Play that resumes; also playlists, recent, search and `showNetworkStream` (whatever mpv reads: http, HLS, RTSP, RTMP). `video_library.dart`: `VideoLibrary`, `VideoHistory` (where each stopped, what's new), `VideoPlaylists`. `play_queue.dart`: order, repeat, shuffle, subtitle files beside a video. `video_player_page.dart`: gestures on phones, keys on computers; sheets for subtitles (embedded, a file beside it, or picked; delay, size, colour), audio tracks and delay, speed, picture, sleep timer, leaving behaviour, hardware decoding. Subtitles are drawn by media_kit's `SubtitleView` (mpv's text), not libass: ASS styling doesn't show. `online_subtitles.dart` searches online with no key or account: Stremio's Cinemeta finds an IMDb id from the title guessed from the file's name (`guessVideoTitle`; the box takes an id too, as it can miss titles) and its public OpenSubtitles add-on lists the subtitles, closest to the file first, by hash and then by shared words. They're saved beside the video as `Movie.eng.srt` (never over a file, a temporary folder for streams), so the player finds them next time. It isn't a service with a promise: api.opensubtitles.com and podnapisi.net didn't connect from this PC, and if the add-on goes, the key-based API at opensubtitles.com is the next thing to try. Outside the app on Android (`core/services/media_controls.dart`, channel `explorer/video_player`): `MediaPlaybackService.kt` is a foreground mediaPlayback service with a MediaSession (notification, lock screen, headset, audio focus); `VideoPlayerNative.kt` does picture in picture, entered by itself on leaving the app while playing. On a computer "picture in picture" is a small window on top, and the tab bar hides (`ExplorerTabs.setChromeHidden`), also in full screen. If mpv's GL context is refused (its log has a fatal `vo/gpu`; every emulator mode does here) the player restarts once and for all with `vo=mediacodec_embed` (`VideoPlayerSettings.directOutput`), so Android's decoder draws: no screenshots then, and only what the hardware decodes. Tests: `test/features/video_player_test.dart` for the logic; `integration_test/video_player_test.dart -d windows` for real mpv (needs ffmpeg on the PATH). Checked on the emulator and Windows, **not yet on a real phone, where mpv's own output has never been seen**; PiP and full screen on computers, Mac and Linux aren't tried either.
- `lib/features/clipboard/`: the clipboard bloc shared by all windows, plus `paste_task.dart` (the copy/move engine: no overwrites, cross-drive moves, streaming).
- `lib/core/services/`:
  - `file_clipboard.dart`: the Windows CF_HDROP clipboard; Linux uses a shared JSON file; macOS uses NSPasteboard (channel `explorer/mac_clipboard` in `MainFlutterWindow.swift`) plus that JSON file for the cut flag. macOS 26 asks before an app reads another app's pasteboard, so Finder files are read only when the user pastes (`readToPaste`, `ClipboardOtherAppFiles`).
  - `file_server/`: HTTP and FTP servers; `only:` limits sharing to the chosen items.
  - `bluetooth_share.dart`.
  - `image_text.dart`: OCR. Windows uses `Windows.Media.Ocr` through Windows PowerShell 5.1; Android uses ML Kit through Play services (`ImageTextNative.kt`); macOS uses Vision (`MainFlutterWindow.swift`, same `explorer/image_text` channel); Linux uses the bundled or system Tesseract.
  - `image_convert/`: `image_formats.dart`, `image_converter.dart` and `heif_writer.dart` (wraps libx265 HEVC from FFmpeg into .heic; checked with libheif). The converter uses Dart `image` for PNG/JPEG/GIF/BMP/TIFF/ICO/TGA/SVG, FFmpeg for WebP/AVIF/HEIC on desktop, and native encoders on Android.
  - `thumbnails/`: `thumbnails.dart` (a queue of file pictures; Windows' shell first, then PDF, Office, raw and design previews), `windows_shell_thumbnail.dart`, `system_icons.dart` (the system's own folder and drive icons at runtime: IShellItemImageFactory on Windows, `explorer/system_icons` in `MainFlutterWindow.swift` on a Mac; never bundle Microsoft's or Apple's icons). `lib/shared/file_icons/`: `file_thumbnail.dart`, `place_icon.dart`.
  - `background_tasks.dart`: tasks shown in the progress dock and the Tasks view (copies, conversions, FFmpeg download, Nearby share transfers).
  - `task_notifications.dart` (Android, channel `explorer/notifications`, `NotificationsNative.kt`): a task that lasts past a tick or two shows in the shade: `headline`, a bar, `message` and `detail` ("234 MB/700 MB"), with Cancel if it can be cancelled, and how it ended if the app isn't in front. The bar is a picture in the theme's gradient (`AppTheme.gradientOf`, `ProgressNotification.kt`, as a RemoteViews ProgressBar can't take one); the video downloader's service uses the same look. Wi-Fi sharing shows too: a tap returns to its screen (`IncomingRoute.fileServer`, `FileServerScreen.showRunning`), Stop stops it. While any ongoing one shows, `BackgroundWorkService.kt` (foreground, dataSync, a wake lock) keeps the app up, and Back at the top of the app moves it behind instead of closing it. Computers have the dock and the tray instead.
  - `video_downloader/`: yt-dlp. The Android engine is downloaded on first use from the `video-engine-0.18.1` release; desktop FFmpeg/Deno go to `<appSupport>/video_downloader`.
- `lib/core/platform/`: `desktop.dart` (new windows via `Desktop.openWindow`, `launcher` hook for tests; on macOS `open -n Explorer.app --args`), `macos_files.dart` (libSystem FFI: volume id, Finder hidden flag, copyfile metadata), `macos_open_files.dart` (Finder Open With / Dock drops via `explorer/open_files` in `AppDelegate.swift`), `background_mode.dart` (close while busy: Windows hides to the tray, Linux shrinks to a Tasks window) `windows_default_app.dart` (which program opens a type: Explorer must never hand a file to itself, that once opened endless windows) and `window_effects.dart` (Options > Window: `WindowBackdrop` through `flutter_acrylic`, plus a Transparency slider, saved as `window_backdrop` and `window_transparency`; Windows defaults to Acrylic at 65%). With an effect on, `AppTheme.shad` makes `background` and `muted` translucent, so paint `background` only once behind anything: layers add up, and four of them once left 30% of what's behind at the 75% setting (`test/features/window_cover_test.dart`; `ShadAppBuilder`'s own is cleared in `main.dart`). `lib/shared/ui/app_glass.dart`: right-click menus (`ExplorerMenu`) and `AppSheet`'s side sheets and dialogs are see-through and blur what's behind them (`GlassSurface`); plain `showDialog` alerts and other `PopupMenuButton`s stay solid, as they have no hook for a blur. On phones the same surfaces use Liquid glass (`AppGlass.isLiquid`, `LiquidGlass`: blur, a little extra saturation, a thin tint, a bright rim and a sheen; Options, saved as `liquid_glass`, on by default), plus the floating top bar in `AppTopBarScaffold`, the drawer and the round button (`AppFab`). It's a look, not Apple's lens refraction.
- `linux/runner/my_application.cc`: the window is shown by `flutter_acrylic` (`Window.initialize()` in `main`), not by the runner. It also sets `_KDE_NET_WM_BLUR_BEHIND_REGION` so KDE on X11 blurs behind the window.

- `windows/runner/`: `drop_files.cpp` (wraps the plugin's drop target to read a drag's file list at the moment of the drop: the plugin keeps what it read when the drag entered, which from WinRAR is only names inside the archive; channel `explorer/drop`, `lib/core/platform/windows_drop_files.dart`), `main.cpp` (a new window cascades from the one that opened it) and `flutter_window.cpp` (tray icon, channel `explorer/tray`: show/hide/notify; it sends clicked/open/quit).

## Releases

GitHub **pre-releases** tagged `vX.Y.Z`:

1. Bump `version:` in `pubspec.yaml` (versionCode +1), commit "Release vX.Y.Z: …", run `python tool/build_release.py`. It writes `build/release/vX.Y.Z/`: 4 APKs and `SHA256SUMS.txt`.
2. **APK signing needs `android/key.properties` and the keystore, which exist only on the main dev PC** (cert SHA-256 starts `86:57:22:49`). Other machines can't build installable updates unless the keystore is copied over securely. Check with `apksigner verify --print-certs`.
3. Tag (annotated), then push `main` and the tag.
4. Run `python tool/release/publish_release.py OWNER/REPO TAG TITLE NOTES.md files…`, which creates the release and uploads, then `tool/release/verify_release.py` to check the uploads. Write notes for app users (what's new, which APK, Windows and Linux install tables; see the v1.0.7 release).
5. Publishing triggers `.github/workflows/desktop-release.yml`, which builds, install-checks and attaches the Windows packages (setup .exe, .msix, .msixbundle, .cer) and Linux packages (deb, rpm, AppImage, flatpak, snap, tar.gz/xz). It can also be run by hand: `python tool/release/actions.py dispatch MSatyam-Mishra/explorer desktop-release.yml main tag=vX ref=vX upload=true`. If some jobs passed and others failed, `tool/release/upload_desktop.py OWNER/REPO RUN_ID TAG WORKDIR` attaches what was built. No Windows zip (the owner doesn't want one).
6. macOS (not in CI): on the MacBook run `flutter build macos --release`, make `build/release/vX.Y.Z/explorer-vX.Y.Z-macos-universal.dmg` with `hdiutil create -volname Explorer -srcfolder <folder with Explorer.app and an /Applications link> -format UDZO`, upload it and add its line to SHA256SUMS.txt (keep the other lines), and keep the notes' "macOS" install section (not notarized: Open Anyway / `xattr -dr com.apple.quarantine`). The python.org Python on the Mac needs `SSL_CERT_FILE=/etc/ssl/cert.pem` for the release scripts; `gh` isn't installed there.
6. Known CI flakiness: the Ubuntu apt mirror can stall. apt now retries with a 30 s timeout, and the package check job is capped at 30 min. The Linux portable bundle carries libmpv and Tesseract (`packaging/linux/system-libs.txt` lists what's left to the system).
